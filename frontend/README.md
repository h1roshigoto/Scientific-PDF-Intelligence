# Scientific PDF Intelligence · Frontend

Светлый интерфейс для Solar и RAG: результаты с поиском и фильтрами, карточка научного контекста, просмотр страниц PDF, реестр документов, замечания и экспорт. Интерфейс использует русский язык и обозначения треков из макета.

## Локальный запуск

Требуются Node.js 22.13+ и pnpm 11.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1
```

Откройте `http://127.0.0.1:5173`. Режим по умолчанию показывает явно отмеченную синтетическую выборку. Контрольные сценарии — Solar D001 / Voc, стр. 5, и RAG D001 / EM, стр. 6. Идентификатор публикации совпадает, поэтому PDF выбирается по полному ключу `solar:D001` или `rag:D001`. Синтетические PDF и CSV можно пересобрать из корня командой `python frontend/fixtures/generate.py` после установки backend.

## API бэкенда

Запустите FastAPI из корня проекта по [инструкции репозитория](../README.md) и заполните `frontend/.env.local` по [.env.example](.env.example). Установите `VITE_DATA_SOURCE=api` и перезапустите Vite. Прокси по умолчанию отправляет `/api/*` на `http://127.0.0.1:8000`. При публикации сборки настройте раздачу файлов из `dist`, SPA fallback для маршрутов и прокси `/api` к бэкенду или задайте `VITE_API_BASE` для доступной точки входа. В браузер попадают только публичные `VITE_*` настройки.

В [контракте](../docs/API_CONTRACT.md) перечислены HTTP-маршруты. UI читает документы, список и деталь результата, замечания, PDF и служебный JSON. Нормализованное значение выводится по данным сервера. Пустое нормализованное значение показано как «—». Нумерация страниц PDF начинается с единицы.

В демонстрационных данных причины допуска, проверка PCE, повторы, доступность полей и приложений передаются через существующие `rule_id`, `reason`, `observed`, `expected`, `result_ids` и `evidence_refs`. Для новых категорий используются демонстрационные идентификаторы правил. Незнакомое правило показывается вместе с причиной и поддерживаемыми ссылками на источники. Согласованный набор идентификаторов и структура дополнительных метаданных ожидаются в handoff бэкенда. Интерфейс выводит полученные статусы и расчёты, а проверку и дедупликацию выполняет backend.

Официальные CSV формирует `spi.csv_export` по [паспорту](../passport.md). Чтобы скачать сформированные файлы из UI, настройте `VITE_CSV_ARTIFACT_BASE` на каталог со статическими подпапками `solar/` и `rag/`. В режиме mock доступны 14 CSV, сгенерированных тем же экспортером для синтетических записей. Текущий HTTP `GET /export/{artifact}` отдаёт только внутренний JSON. Приём пользовательских PDF через браузер ожидает согласованный HTTP-маршрут и контракт состояния обработки. Пакетный импорт доступен через CLI.

Для локальной проверки реального HTTP-стека с синтетическими данными запустите из корня `python frontend/fixtures/serve_api.py` и задайте `SPI_BACKEND_URL=http://127.0.0.1:8001` при запуске frontend в API-режиме. Временное состояние изолировано от рабочей базы.

## Проверки

```sh
pnpm typecheck
pnpm lint
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

С установленным Edge на Windows вместо установки Chromium можно задать в PowerShell `$env:PLAYWRIGHT_CHANNEL='msedge'`. E2E запускает два локальных сервера на портах 4175 и 4176. Отчёт браузерных проверок открывается через `pnpm exec playwright show-report`. JUnit и скриншоты доступны в `frontend/test-results/`. Тесты backend запускаются из корня командой `pytest -q` после установки `.[dev]`.
