# P0 smoke test GigaChat 3 Ultra на Windows

Нужны Python 3.11+, локальные PDF из `dev` и проект GigaChat API с доступом к `GigaChat-3-Ultra`. Согласно документации провайдера, Ultra доступна физлицам в режиме Freemium. Для этого проекта используется scope `GIGACHAT_API_PERS`. Доступ проверяется по `GET /v1/models` и фактическому `model` в ответе `POST /v1/chat/completions`. [Условия доступа к Ultra](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra) · [OAuth и список моделей](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)

## Подготовка и запуск

Из корня репозитория в PowerShell выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
.\.venv\Scripts\python.exe -m spi.gigachat_smoke --prepare-only
```

По умолчанию используются `data/solar/dev/D001.pdf` и `data/rag/dev/D001.pdf`. Другие пути передаются через `--solar-pdf` и `--rag-pdf`. Команда `--prepare-only` сохраняет выбранные фрагменты без подключения к GigaChat.

API и OAuth используют HTTPS с проверкой имени узла и цепочки сертификатов. При недоверенном корневом сертификате возьмите официальные сертификаты Минцифры, добавьте их в доверенное хранилище Windows или укажите путь к PEM-файлу через `GIGACHAT_CA_BUNDLE_FILE`. PEM добавляется к системным центрам сертификации для этого клиента. OAuth-узлу нужен исходящий порт `9443`, API использует `443`. Клиент подключается напрямую. [Инструкция по сертификатам](https://developers.sber.ru/docs/ru/gigachat/certificates)

```powershell
$env:GIGACHAT_SCOPE = 'GIGACHAT_API_PERS'
# При необходимости укажите путь к доверенному PEM-файлу.
# $env:GIGACHAT_CA_BUNDLE_FILE = 'C:\certs\russian_trusted_root_ca_pem.crt'
$credential = Read-Host 'Authorization key из личного кабинета GigaChat' -AsSecureString
$env:GIGACHAT_CREDENTIALS = [System.Net.NetworkCredential]::new('', $credential).Password
try {
    .\.venv\Scripts\python.exe -m spi.gigachat_smoke
} finally {
    Remove-Item Env:GIGACHAT_CREDENTIALS -ErrorAction SilentlyContinue
    Remove-Variable credential -ErrorAction SilentlyContinue
}
```

В `GIGACHAT_CREDENTIALS` передаётся Authorization key из личного кабинета без префикса `Basic`. Можно передать эту переменную через локальное хранилище секретов. Используйте маскированный ввод и храните ключ только локально.

## Формат и проверка

По умолчанию клиент посылает документированный `response_format` с `type: json_schema`, `schema` и `strict: true`. Первый запрос использует синтетический фрагмент. Если API явно отклоняет параметры строгой схемы, оставшиеся запросы просят JSON через промпт. Этот режим можно выбрать и вручную с `--json-only`. В этом режиме гарантии формата ограничены локальной Pydantic-валидацией полученного текста. Даже в строгом режиме клиент проверяет схему и доказательства локально. Один ответ с валидной схемой подтверждает наблюдаемое поведение для данного запроса. [Структурированный вывод GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output)

Обычный прогон включает три последовательных запроса генерации: технический контроль, Solar D001 (PDF-страница 5, Table 1, Pristine, Voc) и RAG D001 (PDF-страница 6, Table 1, RA-CoT, LLaMA3-8B-Instruct, HotpotQA, EM). Если PDF или однозначная привязка ячейки недоступны, соответствующий замер выполняется на синтетическом фрагменте, а научный сценарий остаётся в `needs_review`. При HTTP 401, 403, 404, ошибке TLS, отказе модели или несовпадении модели дальнейшие запросы генерации прекращаются.

PyMuPDF извлекает строки текста и их координаты из визуально сверенных областей таблиц двух D001. В контекст попадают подпись таблицы, уровни заголовков и ячейки нужной строки. Код сверяет метки и выравнивание по координатам, поэтому другая вёрстка страницы может потребовать проверки границ. Цитата должна дословно совпасть с текстом целевой ячейки, а исходное число и единица проверяются отдельно. Для Solar код удаляет разделитель тысяч и делит значение в mV на 1000 через `Decimal`. Для RAG код сохраняет числовое значение дроби. Контрольные значения используются только после локальной проверки доказательств и нормализации. Неоднозначные метки, несовпадение цитаты, ячейки, формата или контрольного результата дают `needs_review`.

Результат сохраняется локально в `outputs/gigachat-smoke/report.json` вместе с файлами подготовленных фрагментов. Поле `local_pdf_cell` содержит наблюдение парсера PDF, а `requests` заполняется по фактическим ответам API. Отчёт содержит статус OAuth и списка моделей, фактическую модель, время каждого запроса в миллисекундах, разбор JSON, проверку схемы, цитаты, ячейки и коды ошибок. Время включает повторы и ожидание между ними. Журнал содержит идентификаторы моделей, этапы, HTTP-статусы и число повторов. Ответы с ошибками и заголовки запросов не выводятся. При штатном завершении онлайн-прогона код 0 означает, что оба научных сценария прошли проверки. Код 1 означает, что как минимум один из них требует дальнейшей проверки.

Тесты с подменой HTTP выполняются без учётных данных:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```
