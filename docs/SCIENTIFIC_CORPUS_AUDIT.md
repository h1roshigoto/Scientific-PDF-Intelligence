# Аудит научного корпуса Solar и RAG

Аудит читает существующие артефакты пакетной обработки и строит план проверки по каждой публикации. Для работы ему достаточно локальных файлов и установленных зависимостей SPI. Сетевые запросы, OCR, извлечение через модель и применение решений о scope не входят в запуск.

## Запуск в PowerShell

Запускайте команду из checkout с установленным SPI и локальным корпусом.

```powershell
python -B -X utf8 -m spi.corpus_audit --verify-pdfs --compare-readiness
```

Укажите корень корпуса при запуске из отдельного checkout.

```powershell
$env:PYTHONPATH = (Resolve-Path ./src).Path
$corpusRoot = '<корень checkout с оригиналами и Store>'
python -B -X utf8 -m spi.corpus_audit --root $corpusRoot --verify-pdfs --compare-readiness
```

| Параметр | Назначение |
| --- | --- |
| `--root` | Корень с `data/<track>/test`. По умолчанию текущий рабочий каталог. |
| `--state` | Store. По умолчанию `outputs/p0-21-test-local/state` относительно `--root`. |
| `--queue` | Каноническая очередь. По умолчанию `outputs/p0-21-test-local/scope-human-review.csv`. |
| `--approval` | Лист согласования. По умолчанию `outputs/p0-22-release/scope-approval.csv`. |
| `--baseline` | Манифест предыдущих подтверждённых scope. По умолчанию `outputs/test-corpus-intake/previously-reviewed-scopes.json`. |
| `--output` | Новый каталог с существующим родителем. По умолчанию новый каталог `spi-corpus-audit-*` в системном TEMP. |
| `--domain` | Значения `solar`, `rag` и `all`. По умолчанию оба трека. |
| `--publication-id` | Один идентификатор без домена, например `P006`. Можно уточнить трек через `--domain`. |
| `--verify-pdfs` | Дополнительно сверяет физическое число страниц и читает встроенные библиографические поля. SHA-256 проверяется при любом запуске. |
| `--compare-readiness [REPORT]` | Сравнивает полные треки с наблюдениями из задания P0 №33a или с явно переданным JSON от `spi.release_readiness`. |

Относительные пути к входам разрешаются от `--root`, путь к отчёту от рабочего каталога. При полном выборе требуется ровно P001–P090 каждого выбранного трека. Фильтр публикации ограничивает отчёт и проверку оригиналов. Реестр, решения о scope и сводка о сохранности issues по-прежнему читаются в целом.

Код выхода 0 (`PASS`) означает, что аудиту удалось проверить входы и сформировать отчёты. Код 2 (`BLOCKED`) означает, что недоступны необходимые входы или снимок изменился. Код 1 (`FAIL`) означает, что нарушен формат, инвариант или завершилась ошибкой операция чтения или записи. При ошибке источников записывается только `diagnostic.json`. Научный gate имеет собственный статус в отчёте.

## Отчёты

| Файл | Содержимое |
| --- | --- |
| `corpus_audit.csv` | Одна строка на оригинал. Scope, текущий checkpoint, фрагменты, OCR, результаты, issues, множество причин и приоритетное действие. |
| `checkpoint_causes.csv` | Строка на проявление причины с полем, значением, фрагментом, ID блока и физической страницей, если они сохранены. `partial_condition` отмечает подтверждённые условия статуса partial. |
| `actions.csv` | Одна задача на публикацию, причину и тип действия. `source_evidence` даёт число наблюдений, примеры и фильтр для полного списка в CSV причин, `blocked_by` показывает зависимости. |
| `corpus_audit.json` | Схема v1, время UTC, SHA-256 входов, сводки, диагностика, источники unresolved, gate, issues, библиография, кластеры связей и план действий. |
| `approved_scope_report.md` | Данные по Solar P002/P006 и RAG P001/P003. Включает состав unresolved до страницы, фрагмента и source block, если эти поля сохранены. |
| `summary.md` | Сводка по обоим трекам, 20 приоритетных публикаций, число задач и сравнение с readiness по запросу. |

CSV сохраняет UTF-8 с BOM. JSON сохраняет типы, в том числе массивы, числа, булевы значения и `null`. Неизвестные значения CSV помечены `UNKNOWN`. Пустой ID фрагмента означает наблюдение на уровне документа или результата. Остальные указатели могут быть `UNKNOWN`. Стабильный снимок даёт одинаковые CSV и одинаковые значения JSON за исключением времени запуска. Храните полные отчёты локально.

## Что подтверждают источники

Scope — решение человека для конкретного SHA-256. Финальные решения сверяются с исходным манифестом, Store, согласованной парой RAG P007/P010 и листом утверждений тем же валидатором, что и release readiness. `scope_status_at_run` отражает состояние на момент обработки. Предложения, указатели страниц и записанное в worksheet подтверждение только одной статьи из спорной пары остаются материалом для последующей проверки.

Checkpoint отражает состояние сохранённого плана обработки. Старый SHA и отсутствующий checkpoint перечисляются отдельно. Записи результатов засчитываются только при наличии текущего SHA в `extraction_metadata`. Модель Store поддерживает `verified`, `needs_review`, `extracted`. Статусы официального CSV `absent` и `present_not_extractable` на уровне записи Store недоступны. `verified` относится к отдельной записи. `processed` относится к плану пакетного запуска. Научную полноту подтверждает отдельная проверка публикации и доступных приложений.

Правило `batch_checks.quality_gate` суммирует unresolved из следующих источников: якоря разметки, сохранённые `pending_units`, уникальные source block ID в пределах каждого review-фрагмента и review-фрагменты без результатов и деталей. OCR и число результатов `needs_review` указаны отдельно. Checkpoint может содержать только количество запланированных или pending-единиц. В таком случае отсутствующие ID восстановить из снимка нельзя. Отчёт показывает известные элементы и число без индивидуальных указателей.

Обычный batch resume сверяет SHA, версию разметки, профиль, схему, режим, версию модельного плана, scope в Store и путь оригинала. При совпадении и отсутствии pending-фрагментов, `pending_units` и `retry_parse` пакетный запуск может пропустить даже `partial`, включая checkpoint с OCR, layout или review. При повторном входе в тот же план цикл переиспользует сохранённые фрагменты со статусом, отличным от `pending`. Локальный режим планирует геометрически найденные фрагменты, но запускает рассмотрение только по табличным ячейкам. Разность между `planned_fragments` и числом сохранённых fragment records требует интерпретации в контексте режима.

## Причины и сигналы

| Код | Сохранённое доказательство |
| --- | --- |
| `OCR_REQUIRED` | Физическая страница перечислена в `pages_needing_ocr`. |
| `PDF_PARSE_RETRY` | Выставлен `retry_parse`. Если сохранены ошибки страниц, они привязаны к странице. |
| `LAYOUT_ISSUES` | Сохранён якорь или запись `layout_issues`. |
| `FRAGMENTS_PENDING` | Есть pending-запись или `pending_units` больше нуля. Только второй случай подтверждает условие partial в batch. |
| `FRAGMENTS_NEED_REVIEW` | Статус фрагмента `review`. Доказательство включает сохранённые коды и указатели. |
| `NO_EXTRACTED_RESULTS` | Задокументирован partial с нулём результатов во фрагментах checkpoint. |
| `CHECKPOINT_ERRORS` | Сохранена ошибка checkpoint или фрагмента, либо статус фрагмента `failed`. |
| `CHECKPOINT_NOT_COMPLETE` | Текущее состояние checkpoint `running` или `failed`. |
| `CHECKPOINT_STALE`, `CHECKPOINT_MISSING` | Checkpoint относится к другому SHA либо отсутствует. |
| `MODEL_REQUEST_BUDGET` | Сохранён явный код `request_budget_exhausted`. Batch обычно останавливается до записи этого кода в checkpoint. |
| `MODEL_CONFIGURATION_ERROR` | Сохранён код `config:…` или `oauth:…`. |
| `UNKNOWN_PARTIAL_CAUSE` | Сохранённый partial без доказанного условия. |
| `SCOPE_NOT_FINAL` | Нет валидированного финального решения. |
| `SCOPE_CHANGED_AFTER_PROCESSING` | Текущий подтверждённый статус отличается от scope на момент обработки. |
| `RESULTS_NEED_REVIEW` | Текущая запись явно помечена `needs_review`. |
| `SCIENTIFIC_CONTEXT_INCOMPLETE` | В записи названы поля `unconfirmed_context`. |
| `NO_VERIFIED_RESULTS` | Для in-scope публикации отсутствуют SHA-связанные verified-записи. |
| `SCIENTIFIC_EVIDENCE_UNKNOWN` | Для включённой публикации недостаёт сохранённых инвентарей checkpoint. |
| `VALIDATION_ERROR` | Связанный scientific issue имеет severity `error`. |
| `METADATA_UNCONFIRMED`, `METADATA_NOT_EXPORTED` | Требуется подтвердить библиографический источник, либо нужное поле есть в Store и отсутствует в проекции экспортёра. |
| `ENTITY_LINKAGE_CANDIDATE` | Два или больше результата имеют общую сохранённую сигнатуру сущности в одной публикации. |
| `ISSUE_NOT_PROJECTED` | Issue может остаться за рамками контракта или проекции из-за отсутствия подходящей verified-записи. |

Причины могут совпадать в одной публикации. Человеческий scope и научные решения оцениваются независимо от технических и submission-наблюдений. Свидетельство из `review` иногда отражает корректное решение оставить неоднозначную запись на проверку.

## Неизменность входов и порядок работы

Аудит читает байты до копирования, сверяет хеши снимка и повторно проверяет входы перед публикацией отчёта. При наличии lock-файлов он кратко занимает существующие резервировки SQLite без записи данных, чтобы не читать Store посреди операции записи. Резервировки освобождаются до построения отчёта. Оригиналы сверяются по названию, пути и SHA-256. Хеши Store, очереди, листа согласования, предыдущих решений и известных файлов release проверяются повторно после подготовки отчётов. Инвентарь содержит относительные имена и числа байтов. Если любой из источников меняется, повторите аудит после завершения записи. Артефакты аудита запрещено писать в Store, оригиналы или официальный каталог релиза.

Сначала согласуйте оставшийся scope и выполните приоритетные задачи четырёх включённых статей. Сверьте страницы OCR и проблемы разметки до подтверждения значений, единиц и происхождения. Следом рассмотрите библиографию, связи и видимость issues. Кластеры связей — предположения с ID источников и уровнем уверенности. Для RAG `metric_k` характеризует метрику, а `top_k` — настройку поиска. Публикационный год не выводится из даты создания PDF. Встроенные метаданные и названия из worksheet требуют проверки. Исключённый по контракту issues.csv или issue без экспортной связи остаётся в Store. Отдельный запуск `spi.release_readiness` отвечает за проверку формата CSV и участнических валидаторов.

Автоматические тесты CI используют только синтетические fixtures. **REAL 180-PDF CORPUS AUDIT: NOT RUN** в CI. Локальный результат и агрегаты описаны отдельно. [P0 №33a](P0_33A_RESULTS.md)
